# Catalog Underwrite Checker

A one-day prototype of a verified analysis workflow for music-catalog portfolios.

**The pattern:** A small workflow that compares what music catalogs actually earned against what was projected when acquired. A script does the math, Claude writes the commentary, and a second agent re-checks every number. Tested with planted errors. Synthetic data.

> All data is **synthetic** (generated by `scripts/generate_data.py`). Nothing here reflects any real company or catalog.

## Why
When an AI writes a financial summary, the risk isn't style, it's a wrong number. This workflow
removes the model from the arithmetic and adds an independent verifier.

## Architecture
```
data/portfolio.db  --> scripts/underwrite_check.py  --> JSON (the only source of numbers)
                                   |
                       Claude drafts out/report.md + out/claims.json
                                   |
                  checker subagent --> scripts/verify.py (re-queries SQL, does NOT reuse the script above)
                                   |
                       APPROVED / REJECTED
```

## Run it
```bash
python scripts/generate_data.py                      # build synthetic DB
python scripts/underwrite_check.py --table           # see the math directly
python -m unittest discover -s tests -v              # prove it catches planted errors
claude                                               # then run:  /underwrite-review
```

## What's planted (and tested)
| Planted issue | Expected result |
|---|---|
| 3 catalogs at ~70%, ~82%, ~88% of underwrite | flagged BELOW_UNDERWRITE |
| 1 catalog fine overall, last 3 months at ~72% | flagged WATCH |
| 1 exact duplicate revenue row | detected, dropped, reported |
| A deliberately wrong figure in a draft | checker returns MISMATCH, exit code 1 |

## 60-second demo
1. Run `/underwrite-review`. Show the ranked flags and the data-quality note.
2. Open `out/claims.json`, change one number, run `python scripts/verify.py out/claims.json`.
3. Show the MISMATCH line. That is the point of the project.

## Limits (honest scope)
- Synthetic data; exponential-decay underwrite is a simplification.
- One skill only. Variance analysis, scenario runs, and distributor reconciliation are natural next skills.
- The checker verifies figures and unsupported causal claims; it doesn't validate the underwriting method itself.

## Extending
Skills are generic. Swap `CLAUDE.md`, `assumptions.md`, and the data source to retarget the agent
(e.g., budget-vs-actuals for FP&A, or a DCF/comps skill reading Bloomberg exports).
